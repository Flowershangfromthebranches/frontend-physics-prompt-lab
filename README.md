# Frontend Physics Prompt Lab

一组用于生成高完成度、单文件、可直接运行的交互式物理/科学前端演示的提示词。

这些提示词的设计目标不是规定模型“应该怎么实现”，而是尽可能固定 **场景、过程和可观察结果**，同时把建模、动画、材质、算法、渲染和工程方案留给模型自行判断。这样可以更直观地观察不同模型在视觉实现、物理连贯性、细节完成度和实现效率上的差异。

## Prompts

### 1. Frozen Soap Bubble

文件：[prompts/frozen-soap-bubble.md](prompts/frozen-soap-bubble.md)

极寒户外雪地中的肥皂泡完整冻结实验。核心过程包括：

- 液态肥皂膜
- 底部成核
- 晶体沿球面扩张
- Snow-Globe Effect
- 多晶体竞争与晶界
- 剩余液膜逐渐冻结
- 完整薄冰壳形成

最终泡泡应保持完整，不爆裂、不坍塌。

### 2. Liquid Nitrogen Rose

文件：[prompts/liquid-nitrogen-rose.md](prompts/liquid-nitrogen-rose.md)

玫瑰浸入液氮、冻结脆化并接受撞击的完整动态实验。核心过程包括：

- 新鲜玫瑰与机械夹持
- 浸入液氮
- 沸腾、气泡与低温冷雾
- 花瓣冻结与霜冻生成
- 柔软组织向低温脆性状态转变
- 提起冻结玫瑰
- 机械撞击
- 花瓣脆裂与碎片落地

## 使用方式

建议在一个干净的工作目录中，将某一份 prompt **单独**交给待使用的 Agent。

Prompt 自身要求最终产物为一个独立的 index.html，直接双击即可运行，不需要 npm、本地服务器或构建步骤。

为了避免额外上下文影响结果，Prompt 中明确要求模型不要使用跨会话记忆、用户记忆、历史聊天记录或过去项目。

## 对比时可以观察什么

除了最终视觉效果，也可以记录完成所需时间。值得直接观察的差异包括：

- 场景和主体建模是否正确
- 透明、薄膜、玻璃、液体、植物、冰等材质是否可信
- 各阶段是否连续而不是简单切换预制状态
- 物体与边界、地面、容器之间是否穿模
- 快慢过程是否具有正确的时间尺度
- 粒子、气泡、冰晶、碎片是否与现象本身存在因果关系
- 前面产生的状态是否能正确延续到最终画面
- 是否存在明显性能、布局或渲染问题
- 模型在未被明确提醒的情况下是否主动处理关键细节

> 建议实际给模型使用时只提供对应 Prompt 文件，不附带本 README，以减少“这是一次评测”之类的额外上下文。
